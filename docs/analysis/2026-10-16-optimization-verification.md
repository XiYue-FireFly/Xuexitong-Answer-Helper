# 2026-10-16 Web 答题优化验收记录

## 范围与结果

按实施前计划完成源码修改，并将用户补充截图中的分类与多选外观问题纳入相同链路。没有提交、推送或发布新版本。

1. 提示词逐题包含 `type`、中文 `typeName`、`answerRule`。单选要求唯一选项，解析拒收多答案；真实多选仍保留多答案。完整提示词上限仍是 300000 字符，整题分批、超限整题跳过。
2. 自动流程先将有效答案入库，按原题 hash 求差，仅重发未取得有效答案的题；收齐所有可发送题后统一填回，不提交。缺题最多自动补发三轮，耗尽后保留已入库答案并提供失败步骤重试。自动模式无需人工确认低置信度警告，手动流程仍保留原确认步骤。
3. 判断题支持 JSON 布尔值，题库和预览显示“正确/错误”。题库新条目保存原始题型，导入导出保留；旧条目按明确类型和严格成对的“对/错”选项兼容分类，不批量改写历史数据。
4. 自动运行开始、重试及恢复时收起侧栏；失败、暂停、长等待提醒和部分完成时展开。拖动增加 pointer capture、WebView 遮罩和失焦/取消清理。控制器继续独立于面板挂载状态运行。
5. 窗口在首次显示前最大化，保留系统任务栏与现有窗口按钮。

## 补充截图根因与回归

| 现象 | 证据与处理 |
| --- | --- |
| 判断题全部归为单选 | 题库条目原先不保存 `QuestionItem.type`；增加可选 type 并优先使用，旧对/错条目兼容识别 |
| 抓题分类可能错误 | 原 DOM 推断遗漏无原生 radio 的判断标题，且通用多选标记优先于明确 qtype；调整为显式元数据优先 |
| 单选多个蓝色圆圈 | 生产 `applyAnswerV2` 的模拟 DOM 用例复现：隐藏答案为 A，但正文子串匹配把内容相似的 B/C 都高亮；改用准确选项身份、值与严格正文匹配 |
| 圆圈过大、选项正文消失 | 原代码把字母圆圈类同时加到整行容器；只在字母标记上使用，并清理容器上该类 |
| 同步可能再次切换选择 | 真实页面桥注入脚本的 VM 用例证明单选也会调用 `addMultipleChoice(qid, values)`；现在仅通知答案卡和内容变化，选择已由点击与 DOM 同步完成 |
| 原生 radio 与字母标记值不同 | 独立审查复现了 value 比较覆盖精确节点的问题；修正身份优先，加入 native checked、hidden answer、marker 三者一致的测试 |
| 等待旧回答被当成格式异常 | 自动坏 JSON 恢复只接受新消息、明确结束且稳定输出；旧 messageKey 或仅尾空白变化不会补发，完整控制器回归确认只发送一次 |
