# DeepSeek 发送等待与回执丢失修复

## 本轮真实现场

- 20:39 左右当前任务仍显示“正在发送提示词”，输入区保留 63,067 字符和六张题图，附件识别结果为 pending。
- 六张图的加载动画自身 visibility=visible、opacity=1、有布局，但每个动画的祖先覆盖层 opacity=0。网页已隐藏动画，适配器却把它识别为仍在上传，因此没有进入发送操作。
- 随后现场提示词已经发出并收到回答，原任务仍保留发送超时。检查发现输入框上的临时准备回执已不存在，旧回执识别依赖该属性。

## 修改

- 附件进度检查逐层检查动画祖先的实际 display、visibility、opacity；透明覆盖层中的动画不再造成永久 pending。
- 状态文字同样排除透明或隐藏区域，避免已隐藏的 Uploading 字样继续触发等待。
- 发送回执改为根据当前请求 ID 和当前批次全部图片文件名核验已发出的消息，兼容输入框重新挂载后临时属性丢失。
- 请求 ID 读取实际批次而非提示词开头的格式示例；旧请求及附件不齐的消息不能通过校验。
- 当前应用已更新序列化适配器，未刷新页面。下次启动会从正式构建 index-DKpdoIof.js 加载修复。

## 验证和恢复

- 新增回归用例均先失败后通过：透明进度覆盖层、隐藏状态文字、输入框重建后的回执与旧请求隔离。
- 完整测试：20 个文件，367 项全部通过；前端及 Electron 构建成功。
- 隔离浏览器验证：透明覆盖层可识别为上传完成，真正上传中的动画仍阻止发送，发送只点击一次，正确识别停止状态。
- 当前真实 DeepSeek 对话只读核验成功：六张图片，输入框为空，回答请求 ID 匹配，输入框临时回执缺失时仍确认 sentReceipt=true。
- 已通过应用现有“从 AI 页面提取答案”操作恢复已有回答，界面显示“确认入库 37 题”，发送超时文字已消失。仅恢复待核对预览，未入库、填写或提交，也未发出新的 AI 消息。
- 证据位于忽略目录：dom-upload-verification.json、current-receipt-verification.json、recovered-current-answer.json、live-send-fix-verification.json。

本轮修复以真实当前故障为依据；其他已观察到的填回选项问题不属于本轮发送与恢复验证。
