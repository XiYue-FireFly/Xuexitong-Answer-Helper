# DeepSeek 卡在“发送提示词”的修复

## 现场证据

- 用户截图显示提示词与图片已进入输入区，发送按钮为无文字标签的图标。
- 实际网页中的发送按钮是 role=button 的 div，使用 ds-button--primary、ds-button--circle 类，没有 aria-label 或 data-testid。旧适配器无法匹配，只能退回 Enter 按键路径。
- 生成期间同一个按钮变成圆角方形停止图标，也没有文字标签。现场观察到输入区已清空、AI 正在思考，旧适配器仍返回 busy=false；此时程序可能继续停留在发送确认阶段。

## 修改

- 在当前输入控件容器内识别唯一的 DeepSeek 主图标按钮，直接调用发送操作。
- 识别 DeepSeek 的 class 禁用状态，禁用时继续等待，不退回 Enter。
- 根据现场停止图标识别正在生成的状态；此时禁止点击主按钮，避免把停止当作发送。
- 查找限定在当前输入区，排除上传及历史区域按钮；保留原来的发送回执检查与防重复发送机制。
- 修复已构建到 index-C6l5SFPM.js。为保留当前网页和任务，在现有窗口的 WebView 桥接调用中替换了序列化适配器；未重启或刷新应用。新启动会直接加载已构建的正式修复。
